# 提案：数据层迁移 - 数据和视图分离

> **Issue**: #11 - 检查数据存储，数据和视图进行分离
> **PR**: #14 - refactor: 数据层迁移 - 实现数据和视图分离
> **状态**: 已合并 (MERGED)

---

## Why - 为什么需要这个变更

### 问题背景

小河日历项目采用 Tauri 跨平台架构，目标支持 Windows、Android、iOS 三个平台。在项目早期实现中，前端直接通过 `@tauri-apps/plugin-sql` 操作 SQLite 数据库，这带来了以下问题：

1. **架构不一致**
   - 外部日历（CalDAV）功能正确地通过 Rust 后端处理
   - 本地日历/待办功能却直接在前端操作数据库
   - 同一应用内存在两种截然不同的数据访问模式

2. **跨平台维护成本高**
   - 每个平台都需要各自的前端实现
   - 数据逻辑分散在多处，修改一处需同步多处
   - 无法共享统一的数据层代码

3. **安全性隐患**
   - 前端代码可被用户直接查看和修改
   - 数据库操作逻辑暴露在前端，缺乏后端保护层

4. **测试覆盖不足**
   - 后端数据操作无自动化测试
   - 前端测试无法覆盖数据库边界场景
   - 集成测试依赖真实数据库，难以隔离

### 业务需求

核心原则明确要求：

> **所有的数据都由 Rust 进行存储和处理，前端根据需要从 Rust 后端获取数据，依据业务需要将数据同步给 Rust 端进行数据存储和更新。前端不直接操作数据库。**

这一原则的实现是项目跨平台战略的基础，为后续多端数据同步、离线优先架构奠定基础。

## What Changes - 具体变更内容

### 架构重构

**迁移前**:
```
前端 Store → database.ts → @tauri-apps/plugin-sql → SQLite
```

**迁移后**:
```
前端 Store → invoke() → Rust 后端 → SQLite
```

### 新增组件

1. **Rust 数据层 (`src-tauri/src/db/`)**
   - `errors.rs` - 结构化错误类型 `DatabaseError`
   - `connection.rs` - 数据库连接管理（支持事务）
   - `schema.rs` - 数据库表结构定义
   - `repositories/` - 5 个数据仓库实现
     - `calendar.rs` - 日历数据仓库
     - `event.rs` - 事件数据仓库
     - `todo.rs` - 待办数据仓库
     - `account.rs` - 外部账号数据仓库
     - `sync_state.rs` - 同步状态数据仓库

2. **Tauri 命令 (`src-tauri/src/commands.rs`)**
   - 日历命令：`get_calendars`, `create_calendar`, `update_calendar`, `delete_calendar`
   - 事件命令：`get_events`, `get_events_by_calendar`, `create_event`, `update_event`, `delete_event`
   - 待办命令：`get_todos`, `create_todo`, `update_todo`, `delete_todo`
   - 账号命令：`get_accounts`, `create_account`, `update_account`, `delete_account`
   - 同步状态命令：`get_sync_state`, `upsert_sync_state`, `delete_sync_state`

3. **前端工具增强 (`src/utils/tauri.ts`)**
   - `safeInvoke` - 统一的 invoke 调用封装
   - 类型安全的参数映射
   - NaN 值处理和回退策略

### 重构组件

1. **前端 Store 重构**
   - `calendar.ts` - 从直接调用数据库改为 invoke 调用
   - `todo.ts` - 从直接调用数据库改为 invoke 调用

2. **删除组件**
   - `src/utils/database.ts` - 原前端数据库操作模块（已移除）

3. **依赖变更**
   - 新增：`rusqlite`, `thiserror`, `tempfile`（用于测试）
   - 保留：`@tauri-apps/plugin-sql`（仅用于外部账号缓存）

## Capabilities - 获得的能力

### 新能力

1. **统一数据层**
   - 三个平台共享同一套 Rust 数据层代码
   - 数据逻辑修改只需一处，自动同步所有平台

2. **结构化错误处理**
   - 前端可区分错误类型（NotFound、Duplicate、Constraint 等）
   - 支持自定义错误消息和恢复建议

3. **后端自动化测试**
   - 150 个 Rust 单元测试覆盖所有仓库
   - 使用内存 SQLite 进行隔离测试
   - 测试覆盖率可量化追踪

4. **事务支持**
   - 原子操作确保数据一致性
   - 支持批量操作的回滚机制

5. **跨平台数据同步基础**
   - 统一后端便于实现多端同步
   - 同步状态仓库已准备就绪

### 能力对比

| 能力 | 迁移前 | 迁移后 |
|------|--------|--------|
| 数据访问方式 | 前端直连数据库 | invoke 调用 Rust |
| 跨平台共享 | 否（需各自实现） | 是（共享 Rust 代码） |
| 后端测试覆盖 | 无 | 150 个单元测试 |
| 错误处理 | 简单字符串 | 结构化类型 |
| 事务支持 | 有限 | 完整事务管理 |
| 安全性 | 前端代码暴露 | 后端逻辑保护 |

- **数据迁移**: 用户需重新配置日历设置（数据库重建）
- **功能兼容**: 所有现有功能保持兼容
- **性能**: 无明显性能变化（invoke 调用开销极小）

- 删除前端直接数据库操作代码
- 统一数据访问模式
- 补充后端自动化测试
