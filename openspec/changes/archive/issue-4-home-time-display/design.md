# Design: 首页时间显示组件

## Context

### 项目背景

小河日历是一款跨平台桌面日历应用，基于 Tauri 2.x + Vue 3 + TypeScript 构建。首页是用户进入应用后的主要视图，当前显示欢迎区域和日程/待办统计数据。

### 技术栈依赖

| 技术 | 版本 | 用途 |
|------|------|------|
| Vue 3 | 3.x | 前端框架，使用 Composition API |
| TypeScript | 5.x | 类型安全 |
| tyme4ts | - | 农历/节气计算库 |
| Pinia | - | 状态管理（本项目未使用） |

### 相关模块

```
src/
├── utils/
│   ├── lunar.ts          # 农历计算核心，提供 getLunarInfo 函数
│   ├── date.ts           # 日期格式化工具
│   └── holidayData.ts    # 节假日和调休数据定义
├── components/home/
│   └── TimeDisplay.vue   # [新增] 时间显示组件
└── views/
    └── HomeView.vue      # 首页视图
```

## Goals

### 主要目标

1. **实时时钟显示**: 提供每秒刷新的时间显示，格式为 HH:MM:SS
2. **完整日期信息**: 显示公历日期、星期、农历日期
3. **节气提示**: 当日若有节气（如立春、冬至等），显示节气名称
4. **节假日标识**: 法定节假日显示特殊标签，突出视觉效果
5. **调休提醒**: 调休补班日显示醒目提醒，避免用户忘记

### 非目标（Non-Goals）

1. **世界时钟**: 不支持多时区显示
2. **秒表/计时器**: 不提供计时功能
3. **历史日期查询**: 仅显示当前日期信息
4. **自定义格式**: 时间显示格式固定，不支持用户自定义
5. **多语言**: 仅支持中文显示

## Decisions

### 决策 1: 组件定位

**选择**: 创建独立的 `TimeDisplay.vue` 组件

**理由**:
- 单一职责原则：时间显示逻辑独立，便于维护
- 可复用性：未来可在其他页面复用
- 测试隔离：独立组件便于单元测试

**替代方案**: 直接在 HomeView.vue 中实现
- **否决理由**: 违反单一职责原则，增加 HomeView 复杂度

### 决策 2: 时间刷新机制

**选择**: 使用 `setInterval` 每秒更新

**理由**:
- 实现简单，性能开销可控
- 每秒刷新满足用户对时间准确性的需求

**生命周期管理**:
```typescript
onMounted(() => {
  timeInterval = setInterval(() => {
    currentTime.value = new Date()
  }, 1000)
})

onUnmounted(() => {
  if (timeInterval) {
    clearInterval(timeInterval)
  }
})
```

### 决策 3: 农历计算库

**选择**: 复用现有 `getLunarInfo` 函数（基于 tyme4ts）

**理由**:
- 项目已有成熟的农历计算逻辑
- 避免重复造轮子
- 保持代码一致性

### 决策 4: UI 设计规范

**选择**: 遵循 Microsoft Fluent Design System

**实现细节**:
| 元素 | 样式规范 |
|------|----------|
| 时间字体 | 52px, font-weight: 600, tabular-nums |
| 卡片圆角 | 16px |
| 节假日标签 | 红/橙色渐变背景，border-radius: 20px |
| 补休提醒 | 黄/橙色渐变背景 |

### 决策 5: 响应式布局

**选择**: 使用媒体查询 `@media (max-width: 600px)`

**适配内容**:
- 时间字体从 52px 缩小至 40px
- 日期区域改为垂直布局
- 农历区域改为垂直布局

### 决策 6: 数据来源

**选择**: 复用现有数据源

| 数据类型 | 来源 |
|----------|------|
| 农历日期 | `lunar.ts` → `getLunarInfo()` |
| 节气 | `lunar.ts` → `getLunarInfo()` |
| 节假日 | `holidayData.ts` → `HOLIDAYS` |
| 调休补班 | `holidayData.ts` → `MAKEUP_DAYS` |

## Risks

### 已识别风险

| 风险 | 级别 | 缓解措施 | 状态 |
|------|------|----------|------|
| 定时器内存泄漏 | 中 | 在 `onUnmounted` 中清理定时器 | ✅ 已解决 |
| 节假日数据过期 | 低 | 文档说明维护方式，需定期更新 | ⚠️ 需维护 |
| 高频刷新性能 | 低 | 每秒刷新开销极小，Vue 响应式优化 | ✅ 无问题 |

### 技术债务

1. **节假日数据维护**: `holidayData.ts` 需要每年更新节假日和调休数据
   - 建议：考虑接入在线节假日 API 或自动化数据源

2. **测试覆盖扩展**: 当前仅覆盖核心功能
   - 建议：后续可增加边界条件测试（如跨日、跨月）

### 依赖风险

| 依赖 | 风险描述 | 应对措施 |
|------|----------|----------|
| tyme4ts | 第三方库，可能有版本更新风险 | 锁定版本，定期评估升级 |
| holidayData | 本地数据，需手动维护 | 文档化维护流程 |
