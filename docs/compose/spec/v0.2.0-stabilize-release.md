# v0.2.0 稳定性打磨与发版

## Report

## [S1] Problem

`release/v0.2.0` 已合入远程账号/云同步、安全架构与性能修复、测试工程化，但：

1. Rust 单元测试无法编译（`CreateCalendarRequest` / `CalendarDTO` 缺少 `read_only` 字段），阻断 `cargo test` 门禁。
2. 版本号仍为 `0.1.2`，CHANGELOG 无 0.2.0 段，无法形成可安装、可更新的正式产物。
3. GitHub Issue #44 功能已在 release 分支实现，但 issue 仍 OPEN，状态与代码不一致。
4. 用户明确要求自动验证、自动交付，不参与日常管理。

## [S2] Design

**范围边界**：只打磨「已开发功能」并交付稳定产物，不新开功能（SQLCipher #80、主题 #57、三端 #58 保持 OPEN）。

**稳定性修复**：
- 为所有测试中的 `CreateCalendarRequest` / `CalendarDTO` 初始化补全 `read_only: false`（生产默认只读关闭）。
- 保证 `cargo test --lib` 可编译并通过；`pnpm test:run` 保持全绿；`pnpm build` 通过。

**发版契约**：
- 版本三处同步为 `0.2.0`：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`。
- `CHANGELOG.md` / `CHANGELOG_USER.md` 新增 `[0.2.0]`，覆盖：远程数据服务、安全架构性能、API 配置重构、测试工程化。
- 合并 `feature/v0.2.0-stabilize-release` → `release/v0.2.0` → `main`，打 tag `v0.2.0` 并创建 GitHub Release。
- 关闭 #44 并说明实现证据；#80/#57/#58 保持开放。

**验收**：
- `cargo test --lib` PASS
- `pnpm test:run` PASS（≥738）
- `pnpm build` PASS
- GitHub Release `v0.2.0` 存在，main 版本号为 0.2.0

## [S3] Out of Scope

- SQLCipher 数据库加密（#80）
- 付费/自定义主题（#57）
- 三端账户模型与反馈入口（#58）
- Android 工程落地
- App.vue 弹窗导航 TODO 的完整交互补齐（可后续迭代）
- 精简面板 region tracking Task 7
